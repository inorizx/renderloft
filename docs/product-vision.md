# RenderLoft 产品愿景

## 一句话

**RenderLoft 把 RunningHub、ComfyUI 和模型 API 提供的生成能力包装成易用的 AI 应用，让用户可以通过参数表单单次或批量完成生成，并统一管理任务与结果。**

## 我们解决什么问题

许多 AI 生成能力已经存在，但使用它们仍然需要用户处理平台差异、API Key、复杂参数、上传素材、远程任务状态和结果整理。

RenderLoft 不重新训练模型，也不替代 RunningHub 或 ComfyUI。它负责把已有能力变成更容易重复使用的应用：

```text
平台 / 工作流 / 模型 API
          ↓
       导入或配置
          ↓
        AI 应用
          ↓
  参数化 · 单次运行 · 批量运行
          ↓
        任务与结果
```

## 能力来源

### RunningHub

RunningHub 上有创作者公开的应用和工作流。用户使用自己的 RunningHub API Key，在 RenderLoft 中通过应用链接或 ID 导入它们。RenderLoft 读取应用的可用参数，生成表单并继续调用 RunningHub 执行。

RenderLoft 保存的是应用的调用配置、参数定义和连接关系，不替代 RunningHub 的创作和托管能力。

### ComfyUI

ComfyUI 是工作流创作和调试工具。用户在 ComfyUI 中完成节点工作流后导出 API Prompt。RenderLoft 的长期方向是按统一的 Recipe 模型接入这类 Prompt，并暴露需要使用的参数；当前正式可用的导入入口以 [`status.md`](status.md) 为准，ComfyUI API Prompt 导入与参数发现仍在完善。

RenderLoft 不做节点编辑器，也不要求用户在 RenderLoft 中重新搭建工作流。接入完成后，它负责提交 API 请求、等待任务完成并整理结果。

### 模型 API

图像、视频以及其他媒体模型的 API，也可以通过连接、参数 Schema 和 Provider 适配器包装成 AI 应用。用户体验与工作流应用保持一致，但底层请求由对应的 API 驱动。

## 用户看到的产品

产品层只需要围绕四件事组织：

1. **连接**：用户配置平台地址、模型和 API Key；密钥通过本地认证 GUI 管理，实际由 Daemon 的凭据存储负责保存和使用。
2. **应用**：一个可执行的 AI 应用，包含说明、输入参数、素材输入和来源信息。
3. **任务**：一次单项或批量执行，以及它的进度和状态。
4. **结果**：生成的图片、视频、音频或其他产物。

代码中的 `Recipe` 是“AI 应用”的领域模型名称；`Connection` 是平台连接；`Operation` 是一次任务；一个批量任务包含多个 `Run`。

## 批量是核心能力

批量不是只给高级用户的附加功能。普通用户和 ComfyUI 用户都需要通过批量提高效率，例如：

- 多条提示词生成多个版本；
- 多张商品图使用同一应用处理；
- 一组参数生成多个变体；
- 多个尺寸、风格或其他参数组合执行；
- 失败项单独重试，结果按输入分组查看。

用户可以把它理解为：

```text
一组输入 → 一次运行 → 一组结果
多组输入 → 一个批量任务 → 多组结果
```

## 三种入口，共享一种执行能力

- **GUI**：默认入口，适合配置连接、导入应用、填写参数、查看结果。
- **MCP**：让外部 AI 发现和调用已经配置好的 AI 应用（它自己决定怎么编排）。
- **CLI**：用于脚本、批处理和开发者自动化。

它们不是三套业务系统，而是同一个本地应用执行核心的不同客户端。表单路径始终是第一公民，即使没有 LLM，用户也能直接运行应用。

## 渐进式使用路径

```text
先配置连接并直接运行应用
        ↓
保存参数、复用历史、批量执行
        ↓
让 MCP 或 CLI 自动调用应用
```

复杂能力逐步增加，但用户的基本路径不应变复杂。当前实现范围见 [`status.md`](status.md)。

## 产品边界

RenderLoft **不是**：

- ComfyUI 节点编辑器；
- RunningHub 的替代平台或完整市场镜像；
- 模型训练平台；
- 让模型直接任意访问网络和本地文件的通用 Agent；
- 必须依赖 LLM 才能使用的聊天产品；
- 以远程 SaaS 多用户账号为前提的服务。

RenderLoft 的价值是：**连接已有能力、应用化、参数化、批量化，并让执行过程可靠可追踪。**

## Local-first 原则

- 平台凭据由用户配置，密钥只交给本地 Daemon 和系统凭据存储。
- GUI、CLI、MCP 共享同一个本地工作区和任务状态。
- 任务状态和结果元数据由本地 Daemon 持久化，界面关闭或重启后可以恢复。
- 用户始终能看到应用来源和使用的连接，不把平台、费用和凭据关系隐藏成不可解释的黑盒。
